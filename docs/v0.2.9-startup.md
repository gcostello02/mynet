# V0.2.9 startup and recovery

## Gather grace (V0.2.8 → V0.2.9)

Production ICE used a fixed **400 ms** sleep after local gathering (`waitGatherComplete`), even when the peer had already sent `gathering_complete`. That added ~300 ms to typical LAN connects on top of ~450 ms STUN gathering.

V0.2.9 waits up to **`MYNET_ICE_PEER_GATHER_GRACE_MS`** (default **100 ms**) for peer gather-done, exiting immediately when the signal arrives. STUN/srflx gathering is unchanged for NAT traversal.

## Recovery metrics

| Field | Meaning |
|-------|---------|
| `ICEAttemptsTotal` | ICE sessions started (includes success) |
| `ICEAttemptsFailed` | Failed ICE session attempts |
| `TransportRecoveries` | ICE transport loss → re-bind cycles |
| `TotalToSuccess` | Wall clock from recovery cycle start to first successful ICE in that cycle |

`RecoveryAttempts` in status now tracks **ICE negotiation failures**, not transport-down count (fixes V0.2.8 mini “attempt 3, recovery 1” confusion).

## VPN readiness

Diagnostics distinguish **ICE data path ready** vs **VPN data path ready** (WireGuard handshake observed via UAPI, optional encrypted traffic).

## Benchmarks

`go test ./internal/connbench -v` runs isolated loopback ICE pair benchmarks (no production coordinator/TUN).
