# V0.3.0 — Always-on VPN and native service management

## Architecture

- **Supervisor owns the process:** launchd (macOS) or systemd (Linux) runs `mynet _daemon` in the foreground.
- **CLI stays unprivileged:** `mynet service status` uses Unix IPC; install/start/stop require `sudo`.
- **Identity preserved:** `MYNET_STATE_DIR` and `MYNET_OWNER_USER` point at the existing user `~/.mynet` tree; no keys in plist/unit files.
- **Always-on VPN:** `MYNET_RUN_VPN_AT_START=1` triggers `Node.Up` when the supervised daemon starts.
- **Manual `mynet up`:** Still works when no system service is installed. If a service is installed but down, the CLI refuses to spawn a competing detached daemon.

## Commands

| Command | Purpose |
|---------|---------|
| `mynet service install` | Write launchd plist / systemd unit + env file |
| `mynet service start\|stop\|restart` | Supervisor control (sudo) |
| `mynet service status` | Supervisor hints + daemon IPC + VPN readiness |
| `mynet service logs` | tail / journalctl |
| `mynet service upgrade` | Stage verified candidate binary |
| `mynet service uninstall` | Remove unit/plist; keep `~/.mynet` |

`mynet down` stops VPN only. `mynet daemon stop` sends IPC quit; warns if a system service is installed.

## Network change recovery

A polling **net watcher** (default route egress fingerprint) debounces changes and closes ICE transports so peer workers renegotiate without treating MyNet TUN as physical uplink.

**Limitation:** Local IP changes on the same default-route interface (e.g. DHCP renew on the same Wi‑Fi SSID) may not change the fingerprint. Existing ICE **transport-down** recovery and peer worker backoff still apply when sessions fail. Sleep/wake may lag up to the poll interval (15s) plus debounce (3s).

## Security notes

- IPC socket mode `0600`; state dir `0700`.
- Service install requires root; templates contain paths only, not secrets.
- `ShouldSpawnDetachedDaemon` reduces duplicate daemon risk when a unit is registered.

### Linux: root + user `~/.mynet`

The systemd unit runs as **root** with a **CapabilityBoundingSet** (not full unrestricted root). User home directories are often `0750` and `~/.mynet` is `0700`, so the daemon needs **`CAP_DAC_READ_SEARCH`** and **`CAP_DAC_OVERRIDE`** to traverse the home directory and create the IPC socket/lock files without loosening permissions on disk. **`CAP_CHOWN`** is required so the daemon can assign `mynetd.sock` / `mynetd.pid` to **`MYNET_OWNER_USER`** (mode `0600`). Interactive `sudo mynet up` does not apply this bounding set, which is why manual V0.2.x could work while the first bounded unit could not.

Supervised `_daemon` does **not** `mkdir` the state directory; install preflight requires an existing identity tree.

`StartLimitIntervalSec` / `StartLimitBurst` belong in **`[Unit]`** so systemd applies restart rate limits.

## Controlled install (not automated in CI)

1. Build candidate: `go build -o bin/mynet-v030-candidate ./cmd/mynet`
2. `sudo mynet service install --binary $(pwd)/bin/mynet-v030-candidate --user $USER` (macOS default: copies candidate to `/usr/local/libexec/mynet/mynet`)
3. `sudo mynet service start`
4. `mynet service status` — verify coordination, WG, VPN data path
5. Rollback: `sudo mynet service stop`, restore prior binary, `sudo mynet service start`
